# Ask about this bill (grounded chat)

An expanded bill opens a persistent **Ask about this bill** chat so the reader can keep asking follow-ups without scrolling past the summary. On desktop the chat docks as the right-hand column (it replaces Vote tightness while that bill is open). On a phone it is a bottom drawer the reader can leave as a peek bar, pull to half, or open nearly full. **Open in ▾** (in the composer toolbar) hands the same briefing to ChatGPT or Claude.

## Sub-features

- `chat-section` renders region `Ask about this bill` next to the bill on desktop (`#bill-chat-rail` / complementary `Ask about this bill`) or in the mobile drawer, with the AI Elements `ConversationEmptyState` (`.bill-chat-empty h3` = `Ask about H.R. 1`; icon + description only on desktop and the drawer's full snap) in the log slot, wrapped `Suggestion` starter chips directly above the composer, and a textbox `Ask about this bill` plus a `Send` button. Enter while a reply streams keeps the draft (no send, no clear); Shift+Enter inserts a newline.
- `chat-desktop-rail` — at `min-width: 1024px`, expanding a timeline bill moves the chat into the right rail (`home-shell--reading`); Vote tightness hides until the row collapses.
- `chat-mobile-drawer` — at `max-width: 1023px` the chat is a non-modal bottom drawer (`dialog` `Ask about this bill`) with peek / half / full snaps. Peek (`--bill-chat-peek` 128px) shows the title plus **Open chat** only; `.bill-chat-drawer-inner[data-snap]` is `peek` / `half` / `full`. **Open chat** lifts to half; **Minimize** returns to peek. **Ask about this** (selection) lifts a peeked drawer to half (including a second Ask of the same passage) and leaves half / full alone. After messages exist, **Send** stays inside the visible snap. The snap column follows the live sheet top while you drag (not only after a snap settles). Focusing the composer must not collapse that column (companion drawer disables vaul `repositionInputs`).
- `chat-open-in` — **Open in ▾** (`Open this conversation in ChatGPT or Claude`, left of **Send** in the composer footer) is the AI Elements `OpenIn` menu: label `Continue in another app`, `Open in ChatGPT` / `Open in Claude` with branded icons and external-link marks, then `Copy briefing`. Each link carries a briefing (bill id, congress.gov + Track Congress URLs, summary, thread). It is not a second local chat.
- `chat-answer` — while the reply is pending a `role="status"` spinner labelled `Answering` sits where the assistant `Message` will land; the answer is Streamdown markdown (`MessageResponse`) and each verified quote is a `[role=log] figure` (blockquote + figcaption such as `Sec. 2. Permitting deadlines · Bill text`) with a `Share this passage` button. The log is `use-stick-to-bottom`: it follows the stream, a `Send` while scrolled up jumps to the bottom, and a `Scroll to latest` arrow appears only after the reader scrolls away. Selecting rendered answer prose and choosing share still verifies against the signed Markdown (bold / list / link syntax is folded on the worker).
- `chat-ask-about-this` — the selection toolbar `Selected text actions` gains `Ask about this`; the selection becomes an inline attachment chip on the composer (with `Remove`) and focuses the textbox.
- `chat-share-passage` — `Share this passage` opens dialog `Share this quote` through the share-quote flow (`source: "bill_text"`).
- `chat-refusal` — when the evidence does not cover the question, the assistant `MessageContent` carries `data-refused` (muted text) and no passages render.
- `chat-error` — a provider failure shows `role="alert"` `The chat service failed. Try again shortly.` with `Retry`; a blank bubble is never shown.

## How to get to it (user POV)

- Expand a timeline bill. On desktop the chat is already on the right. On a phone, pull the bottom bar up (or tap **Open chat**).
- Tap a starter chip or type a question and press Enter / **Send**.
- Select text in **What it does** / **Key points** / CRS summary and tap **Ask about this**.
- Tap **Open in ▾** (next to **Send**) → **Open in ChatGPT** or **Open in Claude** to continue in those apps.

## Gotchas

- The answer comes from a free OpenRouter model, so wording varies between runs; assert on the presence of `[role=log] figure` and that every blockquote is verbatim from the seeded sections, not on the prose.
- The chat is `POST /chat/bill` on the Worker. Vite proxies `/chat` to 8788 in the verify stack; the helper's `api` subcommand is GET-only and cannot exercise it — drive the UI.
- Daily caps (`chat_usage`) are per client per UTC day; the verify D1 is disposable, so a fresh launch resets them, and `npm run seed` also clears `chat_usage` on the shared local D1. A `429` shows `chat-error` with the cap message.
- Each expanded bill has its own conversation (`useChat` id `bill-chat-<bill>`, cached so rail ↔ drawer remounts keep the thread). Home owns one dock; timeline / New laws pass `presentChat` so a detail presents a session. Last present wins; **Ask about this** (`askNonce`) on a background bill steals the dock; a leftover chip does not. Detaching reclaims.
- Desktop chat lives in `#bill-chat-rail`, not at the bottom of `Details for <topic>`. Isolated component tests wrap `FeedRowDetail` with `BillChatLayoutProvider` and `<BillChatPane />`. The rail fills the column (`100vh - --site-rail-top - --site-rail-bottom`, 720px on an 800px viewport); the log slot shows the empty state until the first turn, chips wrap in a flex row just above the composer (not the registry's horizontal `Suggestions` scroller), and the composer footer is `Open in ▾ | Send`.
- `Open in ChatGPT` / `Open in Claude` navigate off-site; do not click through in headed proof — assert `href` only.
- Layout overlay: `?align=1` paints the 8px grid on `html[data-align-grid]`. Leave it off for `qa:web` screenshots.
